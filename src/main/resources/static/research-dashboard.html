Research questions

RQ1

How does intrinsic synchronization around blocking work affect Virtual Threads?

In the tested Java 21 one-carrier condition, synchronized produced direct jdk.VirtualThreadPinned evidence. ReentrantLock removed those observed events, but the serialized 500 ms operation still limited capacity.

Answer: supported, bounded to the tested condition.
RQ2

What must be audited before enabling Virtual Threads?

Audit monitor scope, request-context lifecycle, finite database/external resources, native boundaries, and synchronization semantics. ThreadLocal leakage, Hikari saturation, and universal JNI pinning were not established here.

Answer: supported as a mechanism-specific migration procedure.

Secondary evidence and controls

Extensions that qualify the story

Endpoint isolation

/orders and /products showed zero pinning events. Ordinary blocking, JDBC-shaped work, and cleaned-up ThreadLocal use were not labelled pinning.

JNI boundary

Pure Java sleep: ~713–714 requests; long JNI: ~108–109; short JNI: ~4,185–4,212. All 27 recordings had zero JFR pinning events: behavioral carrier-occupation evidence, not JFR-confirmed monitor pinning.

Hikari sensitivity

H2 and Dockerized PostgreSQL pool sizes 1 versus 10 were nearly identical under the tested 50-VU synthetic closed-loop workload. No pool bottleneck was established.

JDK boundary

Java 24/25 are kept separate from the Java 21 primary result because monitor behavior changed across runtime generations.

Synchronization semantics

Fairness, interruption, ownership, semaphore permits, and CAS state transitions were tested. A replacement must preserve the contract, not just mutual exclusion.

Scheduler probe

Park/unpark handoff was approximately 4.3–8.6 μs on platform threads and 0.4–1.5 μs on Virtual Threads. Mechanism support only, not a universal context-switch cost.

Controls matter

These extensions prevent one slow result from being overinterpreted as a single universal “Virtual Thread problem.”

Thesis-ready wording

Conclusions

Supported: Under the tested Java 21 one-carrier condition, synchronized blocking generated monitor-pinning events; ReentrantLock avoided those observed events.
Supported: Long blocking JNI behaved differently from ordinary Java sleep across the repeated runtime matrix.
Not established: that Virtual Threads are faster in general, that Java 21 outperforms Java 24/25, or that zero JNI JFR events prove no carrier capture.
